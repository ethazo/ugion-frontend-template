# 项目概述

## 定位

ugion 前端项目的可复用起始骨架。它只解决**架构层面**和**布局外壳**的问题,不包含任何业务内容。

每个新项目(临床思维、护理平台、知识库等)从这里克隆一份开始,拿到的是一套已经接好认证、角色分发、布局外壳、请求层和工程约束的地基,直接开始写业务。

## 服务对象

终端用户是医学院的学生与教师,少量医院。

登录角色以 `student` / `teacher` / `admin` 三类为主,少数项目会有额外角色,因此角色集合设计为可扩展而非封闭。

## 模板负责的范围

- 认证与会话引导(应用启动时确认当前用户身份)
- 角色注册表,以及登录后按角色分发到对应外壳
- 布局外壳:用户头像与基本信息、退出登录、主题切换、导航容器
- 请求层与统一的错误、加载、鉴权失效约定
- 主题 token 与暗色模式
- 目录结构与模块依赖方向约定
- 基础工程约束:类型检查、lint、格式化

## 明确不负责

- 任何业务领域模型与业务页面
- 面向教学场景的业务组件(病例、题目、知识点、进度等)
- 传统管理后台那套 CRUD 脚手架
- 测试框架与 CI 流水线

关于最后一条需要强调:**即使是 admin 端也不套用传统管理系统范式**。管理端同样按现代产品的标准设计,筛选、表格、分页这些元素在需要时由具体项目自己组织,模板不预设"管理系统长什么样"。

## 部署约束

项目部署在学校内网服务器上,前端与后端 API 同域。由此产生几条硬性约束:

- 不依赖任何 CDN,字体与图标全部本地化
- 不接入任何外部埋点、错误上报或第三方分析服务
- 构建产物需支持部署在子路径下
- 无需兼容旧浏览器,可直接使用现代 CSS 与 ES 特性

## 复用方式

新项目从模板克隆后各自独立演进,模板的后续改动**不会**回流到已有项目。

这个选择决定了模板的设计取向:追求"克隆的那一刻就是正确的、并且让人敢改",而不是为了跨项目复用去做过度抽象。抽象只在它当场就能让代码更清楚的时候才用,不为未来的复用预留。

## 已确立的前提

- 界面仅中文,不内置 i18n 层
- 暗色模式是必备能力,不是可选项
- 认证基于 Cookie / Session,前端不持有 token
- 单一构建产物,三套角色外壳共存于同一应用内
