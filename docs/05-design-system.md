# 设计系统

## 原则

模板只提供 token 体系和主题机制,不规定产品长什么样。每个项目通过改 token 值形成自己的视觉风格,不需要碰组件代码。

一条明确的取向:**不套用传统管理后台的视觉范式**。即使是管理端,也按现代产品的标准做——留白充足、层级靠间距和字重区分而非靠边框切割、克制使用分割线和阴影。

## Token

Tailwind v4 的 token 写在 `styles/global.css` 的 `@theme` 块里,产出的就是原生 CSS 变量,不需要额外配置文件。

### 颜色

用 oklch 色彩空间,因为它的亮度感知均匀,调深浅时不会像 HSL 那样偏色。

语义化命名,不用色相名。组件里只出现语义 token,不出现具体色值:

```
background / foreground        页面底色与主文字
card / card-foreground         卡片容器
muted / muted-foreground       次级背景与弱化文字
primary / primary-foreground   主色与其上的文字
accent / accent-foreground     强调
destructive                    危险操作
border / input / ring          描边、输入框、聚焦环
```

这套命名跟 shadcn 的约定一致,生成的组件直接可用。

新增语义 token 前先确认现有的是否够用。token 数量膨胀比不够用更麻烦。

### 间距与圆角

间距沿用 Tailwind 默认的 4px 基准刻度,不自定义。圆角定义一个基准变量,组件按它派生,改一处就能整体从方到圆。

### 字体

内网部署不能用 CDN,字体文件本地打包。中文字体体积大,优先用系统字体栈,只在确有必要时引入自定义字体并做子集化。

字号层级控制在 6 级以内,层级过多会让界面失去秩序。

## 暗色模式

### 实现

亮色变量定义在 `:root`,暗色在 `.dark` 下覆盖同名变量。切换就是给 `html` 加减 class,不需要 JS 参与样式计算。

因为组件只引用语义 token,所以适配暗色不需要写 `dark:` 变体——换一组变量值即可。只有极少数情况(如需要在暗色下调整阴影或图片亮度)才用 `dark:`。

### 避免闪烁

主题偏好存 localStorage,初始值跟随系统偏好。关键点是**在 React 挂载之前**就把 class 写到 `html` 上,做法是在 `index.html` 里放一段内联脚本读取偏好并设置 class。否则首屏会闪一下亮色。

### 状态管理

主题状态放 Zustand,是模板里少数几个合理的客户端状态之一。三个取值:`light` / `dark` / `system`,选 `system` 时监听系统偏好变化。

## 组件分层

```
shared/ui/              shadcn 生成的基础组件,可自由修改
layouts/                布局与用户区
features/*/components/  业务组件,只在本 feature 内使用
```

判断一个组件该放哪:

- 不含任何业务概念、换个项目能直接用 → `shared/ui/`
- 与登录用户、导航结构相关 → `layouts/`
- 其余 → 所属 feature 内部

不预先建"公共业务组件"目录。等真的出现两个 feature 需要同一个业务组件时再说,而按 `02-architecture.md` 的规则,那时候更该讨论的是这两个 feature 的边界是否划错了。

## 状态呈现约定

同类状态在所有页面用同一种呈现方式,不各自发挥:

- **加载中**:骨架屏,形状贴近真实内容。不用全屏 spinner 遮罩
- **空状态**:一句说明 + 一个可执行的下一步操作,不只放一句"暂无数据"
- **错误**:说清发生了什么和能做什么,提供重试。不显示原始错误堆栈
- **首屏引导**:启动请求当前用户期间显示极简的加载态,不显示骨架屏(此时还不知道要渲染什么)

这四种态在 `shared/ui/` 里各有对应组件,页面直接用。

## 可访问性

用户群是学生和教师,长时间阅读的场景多,基础可访问性不是可选项:

- 正文与背景对比度至少 4.5:1,大字号至少 3:1
- 所有交互元素可键盘操作,焦点态清晰可见——不允许为了美观移除 focus ring
- 图标按钮必须有 `aria-label`
- 表单控件与 label 正确关联,错误提示与控件建立 `aria-describedby` 关联

shadcn 的基座已处理了组件内部的焦点管理和 ARIA 属性,不要在封装时破坏它。

## 动效

克制。只在能传达状态变化时使用:展开收起、进出场、状态切换。

时长控制在 150–250ms 之间,过长会显得迟滞。尊重 `prefers-reduced-motion`,该设置开启时移除非必要动效。
