# 环境与部署

## 环境划分

只有两种:本地开发和内网生产。没有测试/预发环境,交付方式是把构建产物给到学校服务器。

## 环境变量

用 Vite 的 `import.meta.env`,变量以 `VITE_` 前缀暴露给客户端。

```
.env.example      变量清单与说明,提交进仓库
.env.local        本地实际值,不提交
```

### 变量清单

模板只需要两个:

| 变量 | 用途 | 默认 | 生效阶段 |
| --- | --- | --- | --- |
| `VITE_API_PROXY_TARGET` | 开发代理转发到的后端地址 | `http://main.uniplt.tclocal.ugion.com` | 仅开发 |
| `VITE_BASE_PATH` | 部署子路径,同时喂给 Vite 的 `base` 与 Router 的 `basepath` | `/` | 仅构建 |

注意两者都不是运行时的 API 地址。生产环境前后端同域,请求一律用相对路径 `/api/...`,应用代码里不存在"后端地址"这个概念——`VITE_API_PROXY_TARGET` 只被 `vite.config.ts` 读取,不进产物。

`VITE_BASE_PATH` 必须同时作用于 Vite 和 Router,只配一处会出现资源能加载但路由 404(或反之)。

约定:

- `.env.example` 必须列出所有变量,新增变量时同步更新——它是唯一的变量文档
- 客户端变量全部公开可见,**不放任何密钥**。前端不需要密钥,cookie 认证下凭证由浏览器管理
- 应用代码里的变量在 `shared/` 集中读取并校验一次,不散落 `import.meta.env.XXX`。只被 `vite.config.ts` 用的变量不算在内

变量数量应当保持在这个量级。同域部署省掉了绝大部分配置,新增变量前先确认是不是真的需要。

## 开发环境

### API 代理

生产同域,但本地开发前端和后端不同源,httpOnly cookie 带不上。因此 Vite 配置代理,把 `/api` 转发到后端,让浏览器认为是同域请求。

代理目标由 `VITE_API_PROXY_TARGET` 指定,默认 `http://main.uniplt.tclocal.ugion.com`。**直连真实后端,不用 mock。**

代理有两个必须处理的点,否则登录态在本地跑不通:

- `changeOrigin: true` —— 否则后端按 Host 判断可能拒绝
- cookie 的 domain 需要重写(`cookieDomainRewrite`),后端下发的 cookie 带的是自己的域名,不重写浏览器会丢弃

代理是开发专用配置,不影响生产构建。

### 端口

固定开发端口,避免每次启动变化导致后端的跨域白名单或调试书签失效。

## 生产构建

### 子路径部署

学校服务器上的部署路径不总是根路径,可能挂在 `/app/` 之类的子路径下。因此:

- Vite 的 `base` 与 Router 的 `basepath` 都读 `VITE_BASE_PATH`,默认 `/`
- 应用内不出现硬编码的绝对路径。静态资源用 import 引入,让构建工具处理路径
- 手工拼的 URL 也要带上 base,目前只有 `fileUrl()` 一处(见 `06-api-contract.md`)

这条容易在交付时才暴露问题,所以从第一天就守住。

### 构建目标

现代浏览器基线,不做降级和 polyfill。构建目标设为较新的 ES 版本,产物更小、代码更直白。

### 产物检查

交付前确认三件事:

- 产物中不含任何外部域名请求(CDN、字体、埋点)
- 子路径部署下资源能正确加载
- 打开产物页面无控制台报错

第一条最容易疏漏——新增依赖时可能悄悄引入外部请求。构建后搜一下产物里的 `http` 出现位置即可。

## 服务端配置要点

交付给学校时需要对方(或你自己)在服务器上配置:

- **SPA 回退**:所有非静态资源路径返回 `index.html`,否则刷新子路由页面会 404
- **API 转发**:同域下 API 路径转发到后端服务
- **静态资源缓存**:带 hash 的资源可长期缓存,`index.html` 不缓存

这三条写进交付说明,附一份 Nginx 配置示例,避免每次部署重新解释。

## 内网约束回顾

- 无外网访问,所有资源本地化
- 可能是 HTTP 而非 HTTPS,因此 cookie 不能依赖 `Secure` 标记
- 无外部错误上报,问题排查靠浏览器控制台和后端日志
- 浏览器版本由学校机房决定,但按现代基线要求,交付前确认实际环境版本
